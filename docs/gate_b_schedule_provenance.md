# 게이트 B — 논문 Q3/Q6 수치의 스케줄 출처 규명

작성 2026-07-28. 성격: 로그·이력 조사(측정 아님). 결과: **분기 B-1 확정** (부분적으로 B-3 요소 있음).

---

## 판정 요약

논문 Q3/Q6 수치는 **`ml_misprediction_runtime_bg.yaml`에서 나오지 않았다.** 실행 로그가 기록한 스케줄은
`BoundGuard.yaml`, `Adaptive.yaml`, `Static.yaml`, `Stop-restart.yaml`, `nodwell.yaml`, `reinvoke.yaml`,
`hybrid.yaml` — 실행 시 생성된 **임시 스케줄**이다. 그 실행들이 사용한 모델은 **전부 Table~I 어휘**이며
**전 모델이 inference_count>0**(phantom 뷰 없음)이다.

> **중요 부수 결론**: **phantom 오염은 논문 Q3/Q6 수치에 닿지 않았다.** phantom 어휘를 쓰는
> `ml_misprediction_runtime_bg.yaml`은 논문 실험이 아니라 2026-07-27 v18 계측 세션에서만 2회 실행됐다.

`nodwell`/`reinvoke`/`hybrid`는 **Q6 2×2 ablation의 코너 이름**과 일치하고 전부 07-25에 몰려 있다 — Q6
실행 배치다.

### B-2. Table~I 대조 — **일치**
위 스케줄들이 실제 실행한 모델 집합(로그 집계):
`yolo11s, yolo11m, yolo11l, yolo11x, resnet50, mobilenet_v2, llama1b` — **전부 Table~I 소속**.
phantom 6종(`mnasnet, resnext50, shufflenet-v2-12, squeezenet1.0-12, vgg19, yolov4`)은 **한 번도 등장하지
않는다.** 각 모델의 `inference_count>0` 확인(예: BoundGuard.yaml에서 yolo11s 62건, resnet50 79건,
mobilenet_v2 60건, yolo11m/l/x 각 17~21건).

### B-3. `ml_misprediction_runtime_bg.yaml`의 지위
논문 실험과 무관한 **잔존 파일**이다(v20 감사에서 phantom으로 판정된 그 파일). 07-27 v18 자원 계측에서만
쓰였고, 현재는 v21 fail-fast가 실행을 중단시킨다. → **분기 B-1의 "왜 남아 있는지만 기록하고 격리"** 적용.

### B-4. 원 측정의 비전 모델 개수 — **3-vision 확정**
Q3/Q5 미스프리딕션 런의 워킹셋은 로그상 정확히:

```
llama1b(배경) + yolo11s + resnet50 + mobilenet_v2      ← 비전 3종
```

`yolo11m`은 이 워킹셋에 **없다**(yolo11m/l/x는 별개 워킹셋 `resnet50+yolo11l+yolo11m+yolo11x` 런에만 등장).
관측된 후보 배치:

| 라벨 | 배치 | 대응 |
|---|---|---|
| `combination_stable` | llama1b:GPU, 비전 3종:GPU | top-1(오예측) |
| **`cand_5`** | **llama1b:CPU, 비전 3종:GPU** | **Q3 회복** (legacy rank 5 ✓) |
| **`cand_2`** | **llama1b:CPU, 비전 3종:NPU** | **Q5 회복** (legacy rank 2 ✓) |

논문 서술(Q3 rank 5, Q5 rank 2)과 **정확히 일치** — 논문은 내부적으로 일관되다.
Q6 코너 `nodwell`은 cand_1/2/4/5를 오간 기록이 남아 있어 "wanders onto worse ones" 서술과 부합한다.

## 분기 결정 — **B-1** (논문 수치는 다른 스케줄에서 나왔다)

`ml_misprediction_runtime_bg.yaml`은 이번 작업의 **이식 원본이 아니다.** 격리 대상.
신어휘 스케줄의 원본은 **로그에서 복원한 위 워킹셋**이다.

### 단, B-3 요소가 하나 있다 — 생성기 부재
그 임시 스케줄을 만든 **생성 스크립트가 저장소에 없다**(`scripts/` 전수 검색: 새 어휘 워킹셋 +
코너 라벨을 함께 갖는 파일 없음. `q13_failure_persistence.py`는 옛 어휘 q13 실험용이라 무관).
`fig/` 검증장치와 같은 유형으로 **세션 스크래치에서 증발**했다. 따라서:

- 복원 가능: **모델 구성·디바이스 배치·후보 라벨**(로그에 기록됨).
- **복원 불가: 입력 레이트(`infps`)와 `slo_ms`.** 로그는 달성 fps(예: stable에서 yolo11s 103.6,
  resnet50 235.0, mobilenet_v2 325.2)만 남기고 설정값을 남기지 않는다. 달성 fps는 큐 포화·드롭의
  영향을 받으므로 설정 레이트로 역산할 수 없다.

→ **레이트·SLO는 사람이 확정해야 한다**(아래 §미결).

## 옛→신 대응표 (§2.3 요건)

phantom 이름의 임의 치환은 하지 않았다. 각 이름의 판정과 근거:

| 옛 이름 | 판정 | 근거 |
|---|---|---|
| mnasnet | **폐기** | Table~I 부재, 런타임 레지스트리 부재, 정적 프로파일 부재, **논문 Q3/Q6 원 로그 미등장** |
| resnext50 | **폐기** | 동일 (단 legacy 예측기 데이터셋·q13 스크립트에는 존재) |
| vgg19 | **폐기** | 동일 |
| shufflenet-v2-12 | **폐기** | 동일 |
| squeezenet1.0-12 | **폐기** | 동일 |
| yolov4 | **폐기** | Table~I 부재. `_normalize`가 yolo11s로 별칭 붕괴시켰을 뿐 대응 관계 아님(v21 작업 87로 제거) |

**대응(치환) 항목 없음.** 논문 Q3/Q6 워크로드는 phantom 파일과 무관하므로 번역할 대상이 애초에 없다.
신 스케줄은 **로그에서 복원한 워킹셋**으로 작성한다(phantom 파일 미참조).

## §3 — 2-gen 비전 개수 확정

게이트 B-4로 **원 측정 = 3-vision** 확정. 지시문 §3의 두 번째 분기 적용:

> **재측정하지 않는다.** 2-gen의 주장은 "회복 가능 배치가 예산 밖에 있다"는 존재·순위 주장이고,
> 12/32(3-vision)든 16/64(4-vision)든 $N_{cand}=5$ 밖이므로 논지가 그대로 성립한다.
> **본문에 해당 사례가 3-vision 워킹셋임을 명시**하는 것으로 해소한다(반영은 4단계 패치).

추가로 드러난 사실: **Q3/Q5 본 실험도 3-vision이다.** 즉 §IV-A의 "foreground 4종"과 실제 실행(3종)의
불일치는 2-gen만의 문제가 아니라 **미스프리딕션 계열 전반**에 걸친다. → 아래 미결로 승격.

## 미결 — 사람 판단 필요 (스케줄 생성 진행 전)

게이트 B는 통과했으나(B-1 확정), **스케줄을 확정하려면 두 값이 필요하다.** 임의로 정하지 않는다.

### 미결 1. 전경 모델 개수: 3 vs 4
- **실측(논문 수치의 출처)**: yolo11s + resnet50 + mobilenet_v2 = **3종**.
- **§IV-A 서술**: YOLO11s, YOLO11m, ResNet50, MobileNet-v2 = **4종**.
- 지시문 §2.1은 "논문 서술을 따른다"(4종)이고 §2.1 단서는 "B-1이면 원본 스케줄 구성을 따르되 Table~I과
  어긋나면 보고"(3종)이다. **두 지시가 여기서 갈린다.**
- 선택의 파급:
  - **4종 채택** → §IV-A와 일치하나 **워크로드가 바뀌어 기존 수치와 직접 대조 불가**(경쟁 강도 상승).
    회복 순위도 4/32(정본 랭킹은 4종 기준으로 산출됨).
  - **3종 채택** → 기존 수치와 대조 가능하나 §IV-A 서술과 어긋나므로 **본문 수정 필요**하고,
    정본 랭킹을 3종으로 **재산출**해야 한다(지시문 §7 "랭킹 재생성 금지"와 충돌).

### 미결 2. 입력 레이트(`infps`)와 `slo_ms`
증발한 생성기에만 있었고 로그로 역산 불가. 참고로 정본 랭킹은 대표 레짐
(yolo11s 30, yolo11m 20, resnet50 60, mobilenet_v2 90 fps)으로 산출됐으나 이는 **실측 레짐이 아니다**.
실측 달성 fps(stable, 전부 GPU): yolo11s 103.6 / resnet50 235.0 / mobilenet_v2 325.2 — 설정 레이트는
이보다 높았을 것(드롭 발생 중).

## 하지 않은 것

- **스케줄 생성** — 미결 1·2 확정 전에는 작성하지 않는다(임의 값으로 만들면 재실행 결과가 무의미).
- **phantom 이름 치환** — 전부 폐기 판정, 근거 기록.
- **랭킹 재생성** — 미결 1이 3종으로 결정될 경우에만 필요하며, 그때는 별도 승인 사항.
- **논문 문안 수정.**
