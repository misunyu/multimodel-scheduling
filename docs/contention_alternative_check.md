# 경합 하 대안 존재 여부 (Task B) — Q3 전제 검증

날짜: 2026-07-22 · 측정 전용 · GPU 폴백 0 · 추론-only 처리율 (RTX 5090, sm_120)

## 질문
LLM 배경 부하로 GPU가 경합할 때, 어떤 vision 모델이라도 **경합-GPU 처리율 < CPU 처리율**이 되어
"CPU로 옮기는 것이 더 나은 대안"이 실제로 존재하는가? (존재하면 Q3 오예측 구조 성립.)

## 측정 (처리율 fps, 20 warmup + 100 iter)
| 모델 | CPU | GPU (경합無) | GPU (llama1b×1) | GPU (llama1b×2, 최대) |
|---|---|---|---|---|
| mobilenet_v2 | 199 | 774 | 422 | **268** |
| resnet50 | 19 | 435 | 302 | 224 |
| yolo11n | 17 | 194 | 91 | 53 |
| yolo11s | 6 | 158 | 82 | 51 |

(qwen2_vl은 cuDNN 충돌로 배경에서 제외 → llama1b×2를 최대 경합 대리로 사용.)

## 경합-GPU vs CPU 배율 (최대 경합 기준)
| 모델 | 경합-GPU / CPU | 대안(CPU) 우위? |
|---|---|---|
| mobilenet_v2 | 268 / 199 = **1.35×** | 아니오 (GPU 우위, 경계 최근접) |
| resnet50 | 224 / 19 = 12× | 아니오 |
| yolo11n | 53 / 17 = 3.1× | 아니오 |
| yolo11s | 51 / 6 = 8.5× | 아니오 |

## Task B 판정: **더 나은 대안 없음 (no alternative)**
- **모든** vision 모델에서, 2× LLM 최대 경합에서도 GPU 처리율 > CPU 처리율.
- 경계 사례 mobilenet_v2조차 1.35× GPU 우위 → "애매/판정불가" 아님, **명확히 대안 없음.**
- 추론-only 측정이므로 보수적: CPU 파이프라인은 전처리까지 CPU가 부담 → 실제 파이프라인 μ*에서
  격차는 더 벌어짐(GPU에 더 유리). 결론은 a fortiori 유지.

## 종합 (판정 매트릭스, 사전 고정)
| | A: y2 신호 | B: 대안 존재 | → 결론 |
|---|---|---|---|
| 실측 | **있음** | **없음** | 예측기 정확, Q3 오예측 전제 불성립 |

- 예측기의 all-GPU 선택은 **정당**: all-GPU가 y1·y2 모두 지배하고, 경합 하에서도 CPU 대안이 없음.
- 고λ 경합의 QoS 위반(C3에서 V=342 등)은 **배치 오류가 아니라 용량 문제** — λ가 모든 배치의 μ*를
  초과해 함께 나빠지는 것이며, GPU가 "가장 덜" 나쁨. BoundGuard 후보 순회로 찾을 더 나은 배치 없음.

## 결정: **혼합셋 대규모 구현을 Q3 오예측 시연 수단으로 진행하지 않음**
- Q3 오예측 실험의 두 전제(신호 부재 / 더 나은 대안)가 **둘 다 부재** → 오예측이 발생하지 않음.
- 혼합셋 구현은 Q3 근거로는 정당화되지 않음. (다른 목적—용량/스루풋 스케일링 시연—이라면 별도 판단.)
- 후속 대안 방향(원하면): 오예측을 *만들려면* 예측기가 경합을 못 보게 하는 조건(학습 분포 밖의
  이질 경합) 또는 CPU가 실제로 유리한 초경량 모델/저해상도가 필요 — 현 모델셋엔 없음.
