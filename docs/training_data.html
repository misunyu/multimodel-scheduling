§1The data unit — a contention window

One training row = one (placement, input-rate) combination run under co-execution for a fixed interval Δ (default 8 s, after a 5 s warmup). During the window every active model is fed at its planned rate; the executor records, per application and for the window as a whole: achieved throughput (FPS / tokens-per-sec) and the deadline-miss rate. Each window is tagged with its rate_factor and workload for splitting and normalization.

Measured performance is a label, never a feature — features are built only from the static profile and the placement/rate plan, so predictions require no execution at inference time.

§2Composition

The candidate generator enumerates every feasible placement of a working set, then replicates each across the four input-rate levels. A working set is one detection model plus resnet50 + llama1b + qwen2_vl.

5 workloads (yolo11 n·s·m·l·x)  ×  8 placements  ×  4 rates  =  160 windows
  • Placements per platform. Both accelerators are shareable, so each of the 3 free models picks cpu or the accelerator (qwen2_vl is fixed to the accelerator): 2³ = 8 placements.
  • Input rate. Per-view infps = rate_factor × baseline_rate(model), where the baseline is the model's throughput on its slowest allowed device.
  • Two platforms, two datasets. CPU+GPU (cpugpu) and CPU+NPU / MLA100 (cpunpu), each 160 windows, each trains its own predictor.

§3Train / test split — by input rate

Following the paper, the split is on input-rate level, not random rows: train on 1× / 2× / 4×, hold out 3× entirely. This tests generalization to an unseen workload intensity.

1× · 2× · 4×
train  120 windows (40 each)
3×
hold-out  40 windows

Hyperparameters are chosen inside the training set by 3-fold cross-validation; the 3× hold-out is touched only for final evaluation (evaluate_model.py holdout / select).

§4bAll datasets & predictors

Four datasets were collected on hardware, each training its own predictor. All use the same window schema, feature set, and 1×/2×/4× ↔ 3× split.

The concurrency dataset scales N by adding YOLO11 detectors smallest-first (n, s, m, l, x) on top of resnet50 + llama1b + qwen2_vl; placements are sampled stratified by GPU-count so the whole all-CPU…all-GPU spectrum is covered. Its workload id is N4…N8.

y2 (deadline miss) has a small MAE (0.02–0.16) but a meaningless R² at 3×: under overload the miss rate saturates near 1.0, leaving almost no variance to explain.

Where CPU placement wins. The optimal placement uses the CPU in 16 / 20 CPU+NPU workloads — the MLA100 saturates, so distributing helps. On CPU+GPU it is 0 / 20, and stays 0 even at N=8 concurrent models and any α: all-GPU throughput rises with N (239 → 329 FPS), so the RTX 5090 never saturates and the much slower CPU is worse on both throughput and deadline miss.

§5Features — 37 total

Twelve per-view features are computed for each application instance, then aggregated across the instances of a window by sum, mean, max (12 × 3 = 36) plus the view count (37). The feature set and column order are identical at train and inference time; missing entries are zero-filled.

The 12 per-view base features (aggregated ×3 → 36, + views.count = 37)

No target leakage. Measured throughput, wait time, and inference counts from the run are excluded from features — only static-profile and plan quantities are used, so the same vector is reproducible at inference without executing the placement.

§6Targets & normalization

Three targets are regressed independently so the runtime score's α/β can change without retraining. Throughput targets are normalized to [0,1] per (workload, rate) group by the max observed there — T = F / Fmax — matching the paper. The miss rate is already in [0,1].

§9Window schema

One entry in a performance_*.json data array. The trainer reads total (targets), models (per-view execution for features), and the rate_factor/workload tags.

{ "combination": "combination_37", "window_sec": 8.0, "rate_factor": 1.0, "workload": "yolo11n", "schedule file": "model_schedules.yaml", "models": { "view1": { "model":"yolo11n", "execution":"CPU", // -> features "throughput_fps":3.0, "tokens_per_s":0.0, // -> labels "deadline_miss_rate":1.0, "frames_total":376, "on_time_count":0 }, "view2..4": { ... resnet50 / llama1b / qwen2_vl ... } }, "total": { // window-level TARGETS "total_throughput_fps": 11.84, // -> y1 (raw, normalized later) "total_tokens_per_s": 8.58, // -> y3 (raw) "deadline_miss_rate": 0.875 } // -> y2}
