deploy_cpu_npu & deploy_cpu_gpu — 학습·검증 데이터셋과 피쳐 명세

멀티모델 스케줄링(Mobilint NPU + NVIDIA GPU + CPU)에서 “어떤 모델을 어느 디바이스에 올릴지” 순위를 매기는 두 개의 3-타깃 XGBoost 예측기. 각 예측기의 데이터셋 구성, 37개 피쳐의 유래, 학습/검증 파이프라인, 관련 프로그램과 폴더를 한 곳에 정리한다.

01두 예측기

동일한 레시피(같은 37 피쳐, 같은 타깃 정의, 같은 정규화·마스킹·검증)로 학습된 두 모델. 차이는 배치 대상 디바이스 쌍 하나뿐이다. 두 스케줄은 배치 정렬(같은 자유배치 조합)로 생성되어 플랫폼 간 공정 비교가 가능하다.

플랫폼 분리 근거. 실측 최적 배치를 비교하면 45개 (세트×rate) 그룹 중 30개에서 NPU와 GPU가 서로 다른 배치를 고른다. 패턴은 일관적이다 — GPU는 llama1b(LLM)를 가속기에 올리고, NPU는 CPU에 남긴다. LLM이 없는 vision-only 세트(S1·S2·S9·S10)는 15개 그룹 전부 동일. 하드웨어 특성차가 실제 배치를 갈라놓으므로 예측기를 둘로 유지한다.

02데이터셋 구성

한 행 = 한 측정창(performance window). 하나의 워킹셋을 특정 배치·입력레이트로 실행해 워밍업 20초 후 180초 동안 측정한 결과다. 각 모델당 540행 = 15 워킹셋 × (층화 또는 전수 배치) × rate 3단계.

층화 축 = “가속기에 배치된 모델 수”. 자유배치가 5개 이상인 5개 세트 (S6·S7·S8·S9·S10)는 전 층(0…f)을 커버하되 극단층을 포함하고 중간층을 ≥2로 층화한다. qwen2_vl은 디바이스 제약({gpu, npu})으로 항상 가속기에 고정되어 자유배치에서 제외된다.

홀드아웃 검증 (테스트셋 대신 out-of-fold)

별도 테스트셋을 떼지 않고 3-fold out-of-fold로 검증한다. 각 행을 그 행이 학습에 쓰이지 않은 fold의 모델로 예측해, 예측점수와 실측점수의 (세트,rate)별 Spearman 순위상관을 낸다. 과적합 없이 “배치 순위를 맞히는가”를 정직하게 측정하는 방식이다.

정규화: (models, workload, rate) 그룹 내 [0,1] rate factors: 1.0 / 1.5 / 2.0 / 3.0 / 4.0

03타깃 3종 (y1 · y2 · y3)

한 XGBoost 예측기는 세 개의 부스터(_y1.json / _y2.json / _y3.json)로 구성된다. 배치 점수는 S = y1 − α·y2 (+ β·y3)로 계산하며, 토큰 항(β·y3)은 생성 모델(LLM/VLM)이 실제로 가속기에 있을 때만 더한다. (α=0.3, β=0.5 기본값.)

타깃의미원자료가공
y1 총 처리량 (vision fps 합) Σ throughput_fps (models,workload,rate) 그룹 내 Fmax로 나눠 [0,1] 정규화
y2 데드라인 미스율 deadline_miss_rate 이미 [0,1] — clip만 적용
y3 생성 토큰 처리량 (tokens/s) Σ tokens_per_s 정규화 + 조합단위 마스킹 (아래)
y3 조합단위 마스킹 — 168/540 행 제외. CPU에서 llama1b는 1회 생성에 ~198초가 걸려 180초 측정창에 0–1건만 완료된다 → 토큰 처리량이 순수 노이즈. 따라서 y3는 LLM/VLM 뷰가 실제로 가속기(npu/gpu)에 배치된 조합에서만 유효 라벨로 쓴다(y3_valid). vision-only 세트와 CPU-LLM 조합은 제외되어, y3는 372행으로만 학습된다. 이 마스킹이 없으면 LLM이 없는 세트에도 모델이 ~0.89 tokens를 뱉는 오류가 생긴다.
정규화 그룹 키에 models 포함. yolo11s는 15개 세트 중 9개에서 대표 워크로드라, (workload, rate)만으로 묶으면 2모델 세트의 처리량을 8모델 세트의 Fmax로 나누는 세트크기 혼입이 생긴다. 그룹 키를 (models, workload, rate)로 두어 T = “세트 내 최적 배치 대비 비율”이 되게 한다.

0437개 피쳐의 유래

피쳐는 뷰(view)별 정적 프로파일 + 스케줄 정보에서만 만든다. 측정된 동적 값(실측 fps 등)은 피쳐가 아니다 — 예측 시점에 알 수 없고 타깃을 누설하기 때문이다. 각 뷰에서 12개의 base 피쳐를 만든 뒤 창 단위로 sum · mean · max 3가지로 집계(12×3=36)하고, 여기에 뷰 개수(views.count.views) 1개를 더해 총 37개.

05수집 → 학습 → 검증 파이프라인

한 플랫폼(예: CPU-GPU)의 전체 흐름. 순서가 곧 의존성이다.

  1. 스케줄 생성gen_collection_schedules.py → collect_cpu_{npu,gpu}.yaml + .meta.json (540 조합, 시드 고정, 양 플랫폼 배치 정렬).
  2. 수집 실행collect_run.py가 조합을 랜덤 순서로 실행(schedule_executor_main.py 호출), 워밍업 20s·측정 180s, 20회마다 anchor 재측정, JSONL 증분 저장.
  3. 윈도우 복원jsonl_to_windows.py {npu|gpu}가 JSONL을 performance_*.json 측정창으로 변환.
  4. 데이터셋 빌드build_dataset() — featurize(37 피쳐) + 타깃 정규화 + y3 마스킹.
  5. 최종 학습train_targets() — 타깃별 3-fold CV로 하이퍼파라미터 선택 후 deploy_cpu_{npu,gpu}_{y1,y2,y3}.json 저장.
  6. 정직한 검증out_of_fold_predictions() → (세트,rate)별 Spearman. 최종 아티팩트에 손대지 않음.

하이퍼파라미터

objective: reg:squarederror num_boost_round: 300 CV grid: max_depth ∈ {3,4,5,6}, eta ∈ {0.05,0.1} subsample 0.8 · colsample 0.8 · min_child_weight 3 seed 42 · 3-fold MAE 선택

06프로그램과 사용법

핵심 재사용 코드는 리포지토리에, 이번 재수집(Phase A/B) 실행 스크립트는 세션 스크래치패드에 있다.

프로그램위치역할
deploy_selector_xgb_suite.pyxgboost_model/featurize · build_dataset · train · predict · out-of-fold. 학습/추론의 단일 소스.
gen_collection_schedules.pyxgboost_model/540 조합 수집 스케줄 + meta 생성 (양 플랫폼 배치 정렬).
schedule_executor_main.py(리포 루트)한 조합을 실제 실행해 측정창을 남기는 실행기.
working_sets.yaml(리포 루트)정본 15 워킹셋·rate·층화 정의.
collect_run.pyscratchpad/플랫폼별 순차 수집(anchor·JSONL·크래시복구).
jsonl_to_windows.pyscratchpad/JSONL → performance 측정창 복원.
train_gpu.py / train_npu.pyscratchpad/최종 아티팩트 학습 + out-of-fold 저장.
validate_gpu.py / validate_npu.pyscratchpad/세트별 out-of-fold Spearman 검증.
checkpoint_gpu.pyscratchpad/중간 체크포인트에서 S8 대칭성 확인(아티팩트 비파괴).
compare_platforms.pyscratchpad/NPU vs GPU 실측 최적 배치 비교.
gpu_verify.pyscratchpad/GPU 실제 실행(EP·GPU메모리) 검증, CPU 폴백 배제.

학습 (CLI)

python xgboost_model/deploy_selector_xgb_suite.py train \ --perf_dir <windows_gpu 디렉터리> \ --schedule_dir xgboost_model/schedules/collection \ --static_json xgboost_model/performance_data/sample_profiling_data/sample_profiling_data.json \ --model_out xgboost_model/artifacts/deploy_cpu_gpu

추론 / 배치 순위 (CLI)

python xgboost_model/deploy_selector_xgb_suite.py predict \ --schedule_yaml <후보 배치 스케줄.yaml> \ --static_json xgboost_model/performance_data/sample_profiling_data/sample_profiling_data.json \ --model_in xgboost_model/artifacts/deploy_cpu_gpu \ --alpha 0.3 --beta 0.5 --topk 5

alpha=데드라인 미스 페널티, beta=토큰 처리량 보상. topk로 상위 배치를 뽑는다. NPU 예측기는 deploy_cpu_npu로 --model_in만 바꾼다.
