Reproduction Guide
Rethinking Streaming-Perception Evaluation on Heterogeneous Edge Platforms

Paper source: paper/main_vision.tex (ACCV 2026 submission, ID 624) — read-only source of truth.

What this is: for every figure and table in the paper, the input data, the exact command that regenerates it, and the verification result.

Package: paper/reproduction/ — one folder per figure/table label.

1. Overview

The package under paper/reproduction/ holds one self-contained folder per paper figure/table, named by its LaTeX label (e.g. fig_iou_decay/, tab_main/). Each folder contains:

  • generate.py — the generator, copied verbatim from its original location; the only edits are path constants (inputs → local ./data/, outputs → the folder), each marked with a trailing # [reproduction] path adjusted comment. No computation logic was changed.
  • data/ — a copy of every input the script reads (except one bulky external dataset file; see fig:quant_conf).
  • README.md — label, caption, paper location, inputs, run command, output, the data→artifact transform, and verification result.

Generators that emit a table also cross-check their numbers against the read-only paper/main_vision.tex; the figure generators print value checks against the paper captions. Nothing outside paper/reproduction/ is ever written.

Provenance chain. Raw measurements live in accv_experiments/results/rev*.csv (per-run streaming-AP logs on an RTX 5090 GPU + Mobilint MLA100 NPU, YOLOv11s, Argoverse-HD, 24 logs, ≥3 repeats). The reproduction is pure re-analysis: no new measurement is performed. sAP is reported in percent in the paper (fractions ×100), which is the single most common data→display transform below.

3. Batch reproduction

Regenerate everything reproducible in one shot:

cd paper/reproduction
./run_all.sh                    # auto-detects the repo .venv, or set PY=/path/to/python

run_all.sh runs the 10 runnable generators in paper order and prints an OK/FAILED line per item. It intentionally skips fig:failures (GPU+NPU hardware) and tab:cotenants (descriptive).

Runtime
≈ <1 minute — every item now runs from bundled data (fig:quant_conf renders from its bundled intermediate, no dataset). The optional fig:quant_conf stage-1 rebuild (extract_data.py) adds ~1–2 min and needs the external val.json.
