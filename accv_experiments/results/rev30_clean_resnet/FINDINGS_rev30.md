# FINDINGS — rev30: single-run ResNet50 contention axis (tab:main + Fig2/3a/3b unified)

One canonical measurement set replaces 4 scattered runs (tab:main=rev21/rev20,
Fig3a=rev24/rev22, Fig3b=rev29, Fig2=rev25/sweep_rerun). All tables/figures are
generated by `phase_rev30_aggregate.py` from `rev30_raw.csv` (264 rows) — no hand
transcription. Existing rev* files untouched.

## Method (reused harness, no core edits)
- Independent variable = co-tenant count **k** (ResNet50 GPU loops); frame skip is
  the dependent variable, reported as measured. k∈{0,1,2,3,4,6,8}.
- Reps differ by k: **k=1 → 10 reps** (boundary), k=2/3→7, k=4/6/8→5, k=0→3.
- Deadline = **33.333 ms** (`1000.0/FPS`, FPS=30.0), == `_step_d_common.period_ms`.
- `measure_multistream_full` = verbatim copy of `phase_rev6_sweep.measure_multistream`
  (same `fg_worker`/`per_stream_sap`/`start_bg_custom` primitives), +eff_mean/per-size
  capture, −offline-mAP. **Equivalence asserted on k=0**: worst/mean Δ0.0000, sap_l Δ0.0001.
- **NPU mode = "single" throughout** (`DET["multistream_mode"]`, the established
  multistream mode used by rev22=Fig3a; N=8-capable). Accuracy is mode-invariant:
  All-NPU worst **0.0835** ≈ rev29 global8 **0.0834**. This unifies the NPU mode
  across N=2/4/8 + the split sweep for the first time (rev29's global8 was the odd one out).
- per_stream_sap stored as JSON per cell → Oracle candidates are recomputable
  (fixes the rev20 failure where per-stream sAP was discarded).

## Cross-check vs the old scattered runs (the inconsistency this run resolves)
- rev21/rev20 (old tab:main): Oracle 0.1086, All-GPU 0.0915, skip 35.0 → **0.1086 is INSIDE
  rev30 [0.0975, 0.1089]** ✓
- rev29 (old Fig3b): Oracle 0.0910, All-GPU 0.0887, skip 37.8 → **0.0910 is BELOW rev30 min

  characterizes it as a distribution; the two old values bracket different skip regimes.

## Honest divergences to decide on (this session ran FASTER than the old runs)
1. **k=1 realized skip = 24%, not the paper's ≈38%.** Within this run k=1 is tight
   (24.3±2.2%); the old 31–42% scatter was largely **cross-session**, not within-run.
   If rev30 is adopted, the text "≈38%" / "frame-skip falls from ≈38% to ≈19%" must be
   re-derived from rev30 (and reported as mean±std).
2. **N=2 crossover — RESOLVED by extending to k∈{10,12,16}** (3 reps each, appended;
   273 total rows). N=2 All-GPU now crosses the All-NPU floor (0.0835) between
   k=10 (skip 41.3%, 0.0877) and k=12 (skip 52.1%, 0.0797) → **crossover ≈47%**.
   The "same pattern for N=2,4,8" claim now holds within the single rev30 run:
   - N=2: ≈47%  - N=4: ≈48–50% (45%/0.0868 → 51.5%/0.0819)
   - N=8: crossed from k=0 (8 GPU streams already saturate at k=0 = 58.9% skip).
