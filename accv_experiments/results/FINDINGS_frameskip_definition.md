# FINDINGS — What "GPU frame skip" actually measures (read-only verification)

Scope: pin down, from code + logged CSVs, the exact definition of the **"GPU
frame skip"** quantity in `paper/main_vision.tex` — Table `tab:persize-contention`
(per-size sAP loss vs ≈31/59/100%), Table `tab:main` ("GPU/NPU skip" column),
and Figure `fig:sweeps` (x-axis). No paper, code, config, or result was modified.

## Definitive answers

**Q1 — Whose frame skip is it?**
The **foreground YOLOv11s detector's own deadline-miss rate.** It is the fraction
of the foreground stream's *own* inferences whose effective latency exceeds the
33.3 ms frame period. The ResNet50 co-tenant's work is **not** counted (it is a
bare `while: sess.run()` loop that never produces a frame-skip value).
> `_step_d_common.py:252-259`
> ```python
> # Frame skip = inferences whose effective latency exceeds frame period (33.3ms @30FPS)
> eff_post = result["eff_ms"][WARMUP_FRAMES:] ...
> period_ms = 1000.0 / FPS                       # = 33.33 ms
> n_over = sum(1 for x in eff_post if x > period_ms)
> "frame_skip_pct": 100.0 * n_over / len(eff_post)
> ```

**Q2 — Aggregation across the N=4 foreground streams?**
**Arithmetic mean** of the per-stream `frame_skip_pct` over the foreground
streams placed on that device (4 streams for All-GPU; the GPU subset for mixed).
Not worst, not a single index, not a pooled count.
> `phase_rev25_persize.py:102` (feeds `tab:persize-contention`):
> ```python
> gs = float(np.mean([s["frame_skip_pct"] for s in agg["per_stream"] if s["device"]=="GPU"]))
> ```
> `phase_rev22_sweep.py:52-55` (`dev_skips`, feeds `fig:sweeps` / `tab:main`):
> ```python
> g=[s["frame_skip_pct"] for s in agg["per_stream"] if s["device"]=="GPU"]
> return (round(float(np.mean(g)),1) ... , round(float(np.mean(n)),1) ...)
> ```

## Numerator / denominator of the percentage

Computed **per foreground stream** in `per_stream_sap` (`_step_d_common.py:254-259`),
then averaged:

- **Numerator** = count of that stream's post-warmup inferences with
  `eff_ms > 33.33`. `eff_ms` is the foreground worker's per-inference wall time
  (`fg_worker`, `_step_d_common.py:209,212`: `eff_rt = time.time() - wait_start`;
  in this flow identical to the inference time `rt` that advances the streaming
  clock). The first `WARMUP_FRAMES=30` inferences are dropped before counting.
- **Denominator** = `len(eff_post)` = number of post-warmup inferences that
  foreground stream actually performed (NOT the number of GT frames).
- So per stream it is the **detector's over-budget inference rate**; the reported
  table/figure number is the **mean of that rate across the N=4 foreground
  streams**.

## ResNet50 co-tenant is excluded — confirmed

The co-tenant is launched as a background load thread, never as a measured
stream:
- `_step_d_common.py:342-345` — `_bg_resnet50_loop(stop_event)` is just
  `while not stop_event.is_set(): sess.run(None, feed)`. It has no `result`
  dict, never calls `per_stream_sap`, never appends to `eff_ms` → produces no
  `frame_skip_pct`.
- `agg["per_stream"]` (from `measure_multistream`, `phase_rev6_sweep.py:213-223`)
  contains **only** the foreground `fg_worker` streams. The skip-mean iterates
  over that list, so co-tenant GPU time is felt only as *added latency* on the
  foreground streams, never as a counted "skip."
- Run config matches the `fig:sweeps` text "contention is generated by GPU-bound
  ResNet50 co-tenants": `preload_background_models("L1")` = resnet only
  (`_step_d_common.py:293`), lever = `[_bg_resnet50_loop]*k`
  (`phase_rev22_sweep.py:49`, `phase_rev25_persize.py:45`).

## Cross-stream spread at the ≈59% operating point

The single "≈59%" number hides a **tight** spread across the 4 foreground
streams (they are near-identical, so mean ≈ worst here). Directly logged
per-stream breakdown at the matching operating point
(`rev22_perstream_sap.csv`, `N=4, resnet_k=2, All-GPU, rep0`):

| stream (sid) | per-stream skip % |
|---|---|
| 2  | 57.8 |
| 22 | 56.0 |
| 3  | 54.3 |
| 21 | 54.9 |

mean ≈ **55.8%**, range 54.3–57.8 (spread ≈3.5 pp). (`tab:persize-contention`'s
59% row is the rev25 `skip~58` point, whose per-rep GPU-skip means are
57.6/60.0/58.7 — `rev25_persize_under_contention.csv:13-18`; rev25 logs only the
already-averaged number, not per-stream, which is why the per-stream spread is
quoted from the rev22 run at the same lever.)

## The three conventions are the same quantity — confirmed

- **`tab:persize-contention`** (`main_vision.tex:299-301`): the `GPU frame skip`
  column is rev25's `gpu_skip` (mean over 4 All-GPU streams); the sAP-loss
  columns are the All-GPU per-size sAP drop vs the no-contention row. Verified
  against `rev25_persize_under_contention.csv`: e.g. ≈59% (skip~58) large-object
  loss = `0.4587 − ~0.3635 = 0.095`, small = `0.0078 − ~0.0063 = 0.0015 ≈ 0.002`
  — matches the table's `0.002 / 0.040 / 0.095`.
- **`tab:main`** (`main_vision.tex:312-319`) "GPU/NPU skip (%)" column = All-GPU
  GPU-skip / All-NPU NPU-skip, the **same** mean-of-foreground-streams metric
  under the two homogeneous placements (e.g. ResNet row `35 / 1`).
- **`fig:sweeps`** (`main_vision.tex:333,366`) x-axis = rev22 `gpu_skip`
  (`dev_skips` mean), via `rev24_sweep_byN_points.csv`. Identical definition.

No inconsistency found between the table and the figure: all three are the
foreground detector's mean deadline-miss rate; only the placement / co-tenant
differs.

## Suggested caption/footnote sentence (exact-as-implemented)

For `tab:persize-contention` (and applicable verbatim to `tab:main` /
`fig:sweeps`):

> GPU frame skip is the foreground YOLOv11s detector's deadline-miss rate — the
> fraction of its post-warmup inferences whose latency exceeds the 33.3 ms frame
> period — averaged over the $N{=}4$ foreground streams. The ResNet50 co-tenant
> is the contention source only and is not counted.

Shorter footnote form:

> "GPU frame skip" = mean over the four foreground streams of the fraction of
> their inferences exceeding the 33.3 ms budget; the ResNet50 co-tenant is not a
> measured stream.

(Do **not** describe it as the co-tenant's drops or a pooled all-stream count —
the code averages the foreground streams' own per-inference over-budget rate.)
