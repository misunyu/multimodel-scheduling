# RUN_PLAN (Phase N2-A) — fixed before the campaign

- beta 0.25; rate = beta x Cmax[model] x k, k in [1, 2, 3, 4]; Cmax from `isolated/offline_profile.json`
- warm-up 5 s + window 30 s; driver `/workspace/lib` (sha 92ad...); one run = one executor_npu.py process
- seed 42 (`numpy.random.default_rng`), generated by `code/run_plan_npu.py`; full order in `run_plan.csv`

## Blocks

1. **rep0**: 372 runs = 93 placements x 4 rates. Family order: ybys, rbrsyb, rb, rbrsybys, ys, rsyb, yb, rbrs, rsybys, rs, rbybys; within each family the (rate, candidate) pairs are permuted.
2. **rep1**: 60 runs, 3x of the N>=3 evaluation set (rbrsyb, rbybys, rsybys, rbrsybys), permuted; starts after rep0.
3. **rep2**: 60 runs, same set, a new permutation; starts after rep1.

Total 492 runs; estimate 492 x 40.9 s = 5.59 h (pilot mean incl. overhead).

## Failure handling (fixed)

- A run is failed if its JSON is missing/incomplete/invalid or any NPU sidecar has Close rc != 0. The failed result is kept as `*.rejected.<execution_id>.json` and the run is retried once immediately (logged in `results/retries.csv`).
- If the retry also fails, the campaign stops and is reported. DMA32 free pages < 20,000 before a run: stop and report.
- Interruptions: time, cause and resume point in `logs/campaign_sessions.log`; resume skips runs whose JSON is ok.
